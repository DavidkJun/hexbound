# BUG-016: `BlessingsRow` is too narrow for the 4 slots the spec asks for

| | |
|---|---|
| **Build and seed** | design files at main abced2c (`design/screens.md`, `design/layout.json`) |
| **Severity** | Minor |
| **Owner** | UI / Level designer |
| **Found by** | `tests/auto/design-consistency.test.ts` › `BUG-016 TC-DES-02g` (`it.fails`), while retesting the answer to S-15 |
| **Status** | Open |

**Steps**

1. `design/screens.md` › TopBar: "`BlessingsRow`: one 28 px icon per blessing … It shows **at most 4 slots**: with 5 or more blessings, the 4th slot is a "+N" pill".
2. `design/layout.json` › `MapScreen.BlessingsRow` (and `FightScreen`): `x 427, y 14, w 96, h 28`.

**Expected:** the row fits 4 slots of 28 px: at least 4 × 28 = 112 px plus the gaps between icons. The gap is not specified; `space.xs` would give 124 px.

**Actual:** 96 px, which fits exactly 3 icons with 6 px gaps (3 × 28 + 2 × 6). A 4th icon would overlap the 12 px gap to `LevelName`. `LevelName` is "centred in the remaining space", so its position depends on this width too (TC-DES-02e).

**Suggested fix:**

- Widen `BlessingsRow` in Figma to 4 slots and give the gap between icons a token.
- Re-export `layout.json`, so `LevelName` is re-centred.
