The rule changed in main abced2c, the designer's answer to note N-06. `design/levels/map-format.md` now says:

> A missing `levels.json` is a data error. `npm run check:data` and the built game both show "levels.json is missing", and the game never falls back to loading level files by name. One exception, until the first real map exists: in local development (`npm run dev`) the build may show `_example.json`, with a visible "Example map" warning on screen.

**Steps**

1. Add a real level `data/levels/whisperwood.json` (a copy of the example with `"id": "whisperwood"`), and no `levels.json`.
2. Run `npm run check:data`.
3. Open the built game (`npm run build`, then `npx vite preview`).

**Expected:**

- `check:data` fails with `levels.json is missing`.
- The built game shows the data error screen.
- Under `npm run dev` only, the example map with an "Example map" warning is allowed.

**Actual:**

- `game data: ok`: the level loads silently, in file-name order.
- The built game (and the deployed one) shows the example map with no warning.

**Question for the UI / Level designer and the PM:** read literally, the rule also applies today, while no real map exists. Then:

- `check:data` and CI fail on `main`.
- The deployed build shows "levels.json is missing" instead of the grid, which goes against the programmer's stage 0 "done when" ("the deployed link … shows … an empty hex grid drawn from a map data file").

Suggested wording: "…a data error **once the game set has a level file**. Until the first real map exists, every build shows `_example.json` with the 'Example map' warning." Please confirm before the programmer implements it.
