# BUG-013: a normal or elite enemy is accepted as the boss

| | |
|---|---|
| **Build and seed** | main 73f39a3 · seed: not needed (data check) |
| **Severity** | Minor |
| **Owner** | Programmer (`src/data/level-rules.ts`, `checkBossEnemy`) |
| **Found by** | `tests/auto/map-format.test.ts` › `BUG-013 TC-MAP-10d` (`it.fails`, 2 cases) |
| **Status** | Open |

The rule changed in main abced2c, the designer's answer to note N-05. `design/levels/map-format.md` rule 10 now says: "`boss.enemy` is an existing enemy with `"kind": "boss"`. A normal or elite enemy as the boss is an error." The loader still checks only that the id exists.

**Steps**

1. In `data/levels/_example.json`, set `"boss": { "at": [8, 0], "enemy": "bog-rat" }`. `bog-rat` is `kind: normal` in `data/enemies/_example.json`.
2. Run `npm run check:data`.
3. Repeat with `"frost-wisp"` (`kind: elite`).

**Expected:** `data/levels/_example.json › boss.enemy: "bog-rat" is a normal enemy, the boss must have kind "boss"`.

**Actual:** `examples: ok` in both cases.

**Suggested fix:** in `checkBossEnemy`, pass the enemies (not only their ids) and check `kind === 'boss'`.
