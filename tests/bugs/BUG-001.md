# BUG-001: an enemy with `random` weights `{}` passes the data check

| | |
|---|---|
| **Build and seed** | build b9977c9 (PR #2, `feat/stage-0-project-setup`) · seed: not needed (data check) |
| **Severity** | Major (a rule is wrong, but the run can go on). It becomes a Blocker as soon as such an enemy is fought. |
| **Owner** | Programmer (`src/data/schema.ts`, `movePatternSchema`) |
| **Found by** | `tests/auto/data-format.test.ts` › `BUG-001 TC-DATA-03h` (`it.fails`) |
| **Status** | Open |

**Steps**

1. In `data/enemies/_example.json`, set the first enemy's `pattern` to `{ "type": "random", "weights": {} }`.
2. Run `npm run check:data`.

**Expected:** a problem like `data/enemies/_example.json › [0].pattern.weights: needs at least one move`. An enemy must always have a next move: ui-rules §8 says the intent is always visible.

**Actual:** `examples: ok`. The file loads, and the fight would have no move to pick at run time.

**Suggested fix:** `z.record(...).refine((w) => Object.keys(w).length > 0, 'needs at least one move')`.
